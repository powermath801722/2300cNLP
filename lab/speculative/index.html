01 · Try it

Let a small model guess, let a big model check

distilgpt2 (6 layers) drafts γ tokens one at a time; GPT-2 (12 layers) scores all of them in a single forward pass and accepts each with probability min(1, p/q). One target call can therefore produce several tokens, and the rejection rule guarantees the result is distributed exactly as if GPT-2 had sampled alone. The same text is also generated by GPT-2 alone for comparison.

    02 · Verify the guarantee

    Same distribution, provably and empirically

    For the next token after the prompt, compute GPT-2’s distribution p and distilgpt2’s distribution q exactly, then simulate the accept/reject step many times. Speculative sampling’s empirical frequencies should match p (not q) up to sampling noise; naively keeping every draft token would give q.

    03 · Concepts

    How it works

    Why it helps

    Autoregressive decoding of a large model is memory-bandwidth bound: each step reads all the weights to produce one token. Scoring γ + 1 positions in one pass costs about the same wall-clock time as scoring one on a GPU, so if a cheap draft model guesses right, several tokens come out of one expensive pass. In single-threaded WebAssembly, as here, the extra positions are not free, and distilgpt2 is only about half the cost of GPT-2 because both share the large 50,257 × 768 output layer, so speculative decoding here usually saves GPT-2 calls but not wall-clock time. On GPUs, with a draft model 10–100× smaller, the same algorithm gives the 2–3× speed-ups reported in the papers.

    The acceptance rule

    For each drafted token x ~ q, accept with probability min(1, p(x)/q(x)). At the first rejection, sample a replacement from the residual distribution and stop:

    x′ ~ norm( max(0, p − q) )

    If all γ are accepted, sample one bonus token from p at the next position, so every round yields at least one token.

    Proof sketch: it is lossless

    P(output = x) = q(x)·min(1, p(x)/q(x)) + (1 − Σy min(p(y), q(y)))·(p(x) − min(p(x), q(x))) / (1 − Σy min(p(y), q(y))) = min(p(x), q(x)) + p(x) − min(p(x), q(x)) = p(x). The output is distributed exactly as target sampling, whatever the draft model.

    Acceptance rate and speed-up

    Per token, the acceptance probability is β = Σx min(p(x), q(x)) = 1 − TV(p, q); α = E[β]. With i.i.d. acceptances, the expected number of tokens per target call and the walltime improvement factor are

    E[tokens] = (1 − α^(γ+1)) / (1 − α) speed-up = (1 − α^(γ+1)) / ((1 − α)(γc + 1))

    where c is the draft-to-target cost ratio. Larger γ helps only while α stays high.

    Greedy as a special case

    At temperature 0 both distributions are one-hot: a draft token is accepted exactly when it is GPT-2’s argmax, and the replacement is GPT-2’s argmax. The output then equals plain greedy decoding token for token, which this page checks.

    Variants

    Self-speculation drafts with early layers of the target itself; Medusa adds extra decoding heads; EAGLE drafts at the feature level; lookahead and prompt-lookup decoding guess from n-grams already in the context; tree-based verification checks several draft branches in one pass. All keep the same accept/reject core when exactness is required.
